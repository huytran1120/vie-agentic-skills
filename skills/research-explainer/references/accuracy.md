# Accuracy rules

The video is a scientific statement. A viewer cannot ask a follow-up question, so everything shown must be defensible.

## Claims ledger (claims.json)
```json
{"claims": [
  {"id": "c7", "statement": "(fictional example) Method A cuts the error rate from 12.0% to 4.5% on dataset X (500 test items).",
   "values": ["12.0", "4.5", "500"], "status": "final",
   "source": "paper.pdf p.7 Table 3 / results/table3.csv / run 2026-01-15_a",
   "caveat": "Only on in-distribution items; on the shifted split the gain is 2 points."}
 ],
 "ignore_numbers": ["2024"]}
```
- `values`: numbers exactly as the narration writes them (use data.json for measured values; rx.py claims also accepts any
  value in assets/*.json at the same rounding, including x100 for percentages).
- `status`: final (finished, will not change), reported (from someone else's paper, as they report it), development
  (measured on a development set / pilot), in progress, planned (not run yet: never show a number), preliminary,
  illustration (a constructed example, not a result).
- `ignore_numbers`: years, figure numbers, section numbers; never results.
- `rx.py claims` fails on any number in the narration without a match. Small integers (≤10) are flagged for checking only.

## Writing rules
1. Same definitions as the source. If the paper's "success" counts something specific, say what it counts or use their term.
2. Denominators always: "18 of 20", "on 500 items", "20 trials". Percentages without a base are not allowed on screen.
3. Status on screen: every result chart/number carries a `tag()` with its status, and a `source_note()` with its origin.
4. Keep the caveats from the ledger. If the text-only version is condensed, numbers and caveats stay; adjectives go.
5. Show where the method is not best, if the sources show it. One honest comparison scene is worth more than three wins.
6. Reported vs reproduced: a number from another paper is "reported"; if we reproduced it, say "our reproduction" and give
   the agreement ("all 30 cells within 5 points").
7. No extrapolation: "works on CIFAR-10" never becomes "works on images".
8. Collections of papers: attribute each number to its paper on screen; don't place numbers from different settings on
   one axis without a visible note.
9. Planned work is described in words, never with expected numbers.
10. Anything generated by an image model is decoration, labelled as such if it could be mistaken for data.

## Review pass (before delivery)
- Walk the narration beat by beat against the ledger.
- Optional but recommended: a separate reviewer agent with the sources, the ledger and the narration, asked to find
  overstatements, missing caveats, wrong statuses and numbers that do not match the source. Fix and re-run rx.py claims.
