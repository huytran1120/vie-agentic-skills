Làm chủ Claude API: Từ Prompt Engineering đến Tool Use chuẩn AnthropicMastering Claude API: From Prompt Engineering to Tool Use the Anthropic Way

Biên soạn bởi Vie Agentic Skill · Dựa trên tài liệu chính thức từ AnthropicPrepared by Vie Agentic Skill · Based on official Anthropic documentation

Khi phát triển ứng dụng hoặc xây dựng AI agent với mô hình Claude, phần lớn kỹ sư thường bắt đầu bằng việc thử nghiệm prompt tự do trên giao diện chat rồi đưa thẳng vào mã nguồn. Khi mô hình phản hồi thiếu nhất quán hoặc vỡ định dạng dữ liệu, phản xạ phổ biến là điều chỉnh từ ngữ theo cảm tính. Để thiết lập chuẩn mực kỹ thuật tin cậy, Anthropic đã phát hành bộ giáo trình thực hành tương tác chính thức anthropics/courses.

When building applications or AI agents with Claude models, engineers often draft prompts casually in a web interface before committing them directly into production code. When the model outputs inconsistent responses or malformed data structures, developers typically tweak phrasing based on guesswork. To establish rigorous engineering standards, Anthropic published its official interactive hands-on curriculum: anthropics/courses.

1. Giáo trình anthropics/courses: Vì sao lập trình viên cần học?1. The anthropics/courses Curriculum: Why Developers Need It

Kho mã nguồn anthropics/courses là tập hợp các bài giảng tương tác dưới định dạng Jupyter Notebook (.ipynb), cung cấp mã nguồn mẫu, sân chơi thử nghiệm (playground) và bài tập có đáp án chuẩn. Thay vì các mẹo vặt trôi nổi trên mạng xã hội, bộ tài liệu phản ánh chính xác cơ chế huấn luyện (reinforcement learning and constitutional alignment) mà Anthropic áp dụng cho các phiên bản Claude 3, 3.5 và các thế hệ tiếp theo.

Điểm đặc biệt của kho học liệu này là tính thực dụng cao: toàn bộ bài tập đều được thiết kế mặc định chạy trên mô hình gọn nhẹ claude-3-haiku hoặc claude-3-5-haiku nhằm tối ưu chi phí token cho học viên, đồng thời cung cấp cả phiên bản cho AWS Workshop và Google Cloud Vertex AI.

The anthropics/courses repository collects interactive lessons in Jupyter Notebook (.ipynb) format, supplying reference code, interactive playgrounds, and validated solution keys. Rather than fragmented social media tips, these materials directly reflect the training paradigms (reinforcement learning and constitutional alignment) engineered by Anthropic for Claude 3, 3.5, and subsequent generations.

A notable strength of this curriculum is practical economy: all hands-on exercises default to the cost-efficient claude-3-haiku or claude-3-5-haiku models, keeping API experimentation costs minimal while also providing adapted editions for AWS Workshop and Google Cloud Vertex AI.

2. Lộ trình 5 cấp độ chuẩn hóa năng lực phát triển2. The 5-Level Developer Competency Roadmap

Anthropic đề xuất người học hoàn thành 5 module theo trình tự tuần tự để xây dựng nền tảng vững chắc:

Khóa học Thư mục mã nguồn Trọng tâm kỹ thuật Sản phẩm đầu ra
1. API Fundamentals anthropic_api_fundamentals Messages API, tham số điều khiển (temperature, top_p, top_k), streaming chunk và xử lý ảnh đa phương thức (Vision). Client SDK hoàn chỉnh, xử lý stream mượt mà, tối ưu thời gian phản hồi đầu tiên (TTFT).
2. Prompt Engineering Tutorial prompt_engineering_interactive_tutorial Cấu trúc prompt 9 chương, vai trò system/user/assistant, tách dữ liệu bằng thẻ XML, suy nghĩ từng bước và chống ảo giác. Mẫu prompt đạt độ chính xác cao, loại bỏ hoàn toàn nguy cơ prompt injection từ văn bản người dùng.
3. Real World Prompting real_world_prompting Văn cảnh lớn (long-context documents), trích xuất thực thể phức tạp, phân loại đa nhãn và xử lý lỗi ngữ nghĩa. Hệ thống trích xuất dữ liệu từ hợp đồng, báo cáo tài chính không bị hiện tượng thất lạc thông tin ở giữa văn bản.
4. Prompt Evaluations prompt_evaluations Xây dựng test suite tự động, assertion-based testing, mô hình chấm điểm (LLM-as-a-judge) và phân tích hồi quy prompt. Ma trận đánh giá định lượng, ngăn chặn tình trạng cải thiện ca kiểm thử này nhưng làm hỏng ca kiểm thử khác.
5. Tool Use tool_use Định nghĩa JSON Schema cho công cụ, ép định dạng đầu ra có cấu trúc, hoàn thiện chu trình lặp client-model và chatbot đa công cụ. AI Agent tự hành có thể truy vấn cơ sở dữ liệu, đọc ghi tập tin và phối hợp nhiều công cụ an toàn.

Anthropic recommends working through the 5 modules sequentially to establish a sound engineering foundation:

Course Module Directory Technical Focus Primary Deliverable
1. API Fundamentals anthropic_api_fundamentals Messages API, hyperparameters (temperature, top_p, top_k), streaming chunks, and multimodal image handling. Robust SDK clients featuring low Time to First Token (TTFT) streaming integrations.
2. Prompt Engineering Tutorial prompt_engineering_interactive_tutorial 9-chapter curriculum on system/user roles, XML data separation, chain-of-thought, and hallucination reduction. Resilient prompts immune to input data leakage and prompt injection.
3. Real World Prompting real_world_prompting Long-context window handling, entity extraction, multi-label classification, and complex edge-case remediation. Production extractors for contracts and technical documents avoiding lost-in-the-middle degradation.
4. Prompt Evaluations prompt_evaluations Automated test suites, deterministic assertions, LLM-as-a-judge patterns, and regression prevention. Quantitative benchmark matrices ensuring prompt edits do not break existing test cases.
5. Tool Use tool_use JSON Schema specifications, structured outputs, full client-model feedback loops, and multi-tool orchestration. Autonomous AI agents capable of querying external databases, APIs, and file systems reliably.

3. Cấu trúc thẻ XML và kỹ thuật Prefilling phản hồi3. XML Tag Architecture and Assistant Prefilling

Một trong những điểm khác biệt lớn nhất giữa Claude và các dòng mô hình khác là khả năng phân tích cú pháp dạng thẻ XML cực kỳ nhạy bén. Thay vì viết văn bản liền mạch hoặc dùng markdown thông thường, Anthropic khuyến nghị phân tách rõ ràng các thành phần của prompt bằng các cặp thẻ như <context>, <instructions>, <examples> và <thinking>.

Đặc biệt, kỹ thuật Prefilling Assistant Response cho phép lập trình viên định sẵn vài ký tự mở đầu trong lượt phản hồi của trợ lý ảo. Nhờ đó, mô hình bị ràng buộc phải tiếp tục câu trả lời từ tiền tố đó, loại bỏ hoàn toàn phần rào đón dông dài và đảm bảo định dạng JSON hợp lệ 100%.

Python: Cấu trúc Prompt XML và Prefilling chuẩn Anthropic
import anthropic

client = anthropic.Anthropic()

system_prompt = """You are an expert code auditor. Analyze submitted snippets for vulnerabilities.
Follow these steps inside <thinking> tags:
1. Identify all user inputs and untrusted data flows.
2. Check for buffer overflows, SQL injection, or unvalidated deserialization.
3. Formulate the final verdict in valid JSON inside <result> tags."""

user_prompt = """<code_to_review>
def execute_query(db, user_query):
    cursor = db.cursor()
    cursor.execute(f"SELECT * FROM accounts WHERE id = '{user_query}'")
    return cursor.fetchall()
</code_to_review>

Please conduct your review."""

response = client.messages.create(
    model="claude-3-5-haiku-20241022",
    max_tokens=1024,
    system=system_prompt,
    messages=[
        {"role": "user", "content": user_prompt},
        # Prefill buộc mô hình mở thẻ thinking trước khi đưa ra kết quả
        {"role": "assistant", "content": "<thinking>\n1. Analyzing untrusted flow:"}
    ]
)

print(response.content[0].text)

Kỹ năng prompt-engineering trong danh mục VAS tổng hợp toàn diện các mẫu cấu trúc này, giúp bạn áp dụng ngay vào dự án mà không cần viết lại từ đầu.

A distinctive capability of Claude models is their proficiency in parsing XML markup. Rather than writing unstructured prose or markdown headings, Anthropic strongly advises delineating prompt components with explicit tags such as <context>, <instructions>, <examples>, and <thinking>.

Furthermore, Assistant Prefilling allows developers to seed the beginning of the assistant's turn. Because the model must continue from the provided tokens, conversational filler is eliminated and JSON schemas are completed deterministically.

4. Đo lường chất lượng với Prompt Evaluations tự động4. Measuring Quality with Automated Prompt Evaluations

Một sai lầm kinh điển trong phát triển ứng dụng AI là đánh giá chất lượng prompt dựa trên cảm nhận chủ quan (vibe check): thay đổi vài từ trong prompt, kiểm tra thủ công với 1 hoặc 2 câu hỏi mẫu, thấy kết quả hợp lý rồi đưa thẳng lên production. Cách làm này ẩn chứa rủi ro hồi quy (regression) cực lớn, bởi vì việc tinh chỉnh cho một trường hợp góc (edge case) thường làm suy giảm độ chính xác ở hàng chục trường hợp thông thường khác.

Module prompt_evaluations trong khóa học hướng dẫn quy trình kiểm thử hai lớp:

  • Kiểm thử xác thực trực tiếp (Deterministic Assertions): Sử dụng hàm kiểm tra mã nguồn (JSON schema validator, regex, keyword inclusion) để xác minh các ràng buộc cứng không phụ thuộc vào LLM.
  • Mô hình giám khảo (LLM-as-a-Judge): Sử dụng mô hình cấp cao hơn (như Claude 3.5 Sonnet) với bảng tiêu chí (rubric) chấm điểm chi tiết từ 1 đến 5 để đánh giá các yếu tố trừu tượng như độ mạch lạc, tính hữu ích và sự an toàn.

A classic pitfall in AI software engineering is assessing prompt modifications solely through subjective inspection: tweaking phrasing, manually spot-checking a few sample queries, and deploying without regression testing. This approach introduces severe regressions, as adjustments targeted at one edge case frequently compromise accuracy across dozens of core user journeys.

The prompt_evaluations module establishes a dual-layer testing methodology:

  • Deterministic Assertions: Fast, programmatic validators (JSON schema checkers, regex patterns, key existence checks) verifying strict invariants without additional token overhead.
  • LLM-as-a-Judge Evaluation: Leveraging a higher-tier model (such as Claude 3.5 Sonnet) governed by detailed rubrics scored on a 1-to-5 scale to evaluate abstract properties including tone, coherence, and safety boundaries.

5. Vòng lặp Tool Use và tích hợp vào Agent Skill5. The Tool Use Feedback Loop and Agent Skill Integration

Khóa học tool_use giải thích chi tiết cách chuyển đổi Claude từ một mô hình trò chuyện thụ động thành một tác tử hành động (Agent). Vòng lặp tương tác chuẩn bao gồm 4 giai đoạn khép kín:

  1. Khai báo công cụ: Client gửi danh sách công cụ với tên, mô tả chức năng và JSON Schema quy định kiểu dữ liệu của các tham số.
  2. Quyết định kích hoạt: Claude phân tích ngữ cảnh người dùng và trả về khối tin nhắn có kiểu tool_use kèm ID phiên gọi và giá trị tham số đã trích xuất.
  3. Thực thi cục bộ: Ứng dụng phía máy khách nhận diện yêu cầu, thực thi hàm nghiệp vụ (như truy vấn SQL hoặc gọi API) trong môi trường an toàn.
  4. Phản hồi kết quả: Client gửi lại tin nhắn mang vai trò tool_result tương ứng với ID gọi ban đầu để Claude tổng hợp câu trả lời hoàn chỉnh.
JSON: Cấu trúc khai báo Tool Schema chuẩn
{
  "name": "search_codebase",
  "description": "Searches repository files for exact symbols or regex patterns. Always use this before editing code.",
  "input_schema": {
    "type": "object",
    "properties": {
      "query": {
        "type": "string",
        "description": "The symbol, function name, or regular expression to locate"
      },
      "file_pattern": {
        "type": "string",
        "description": "Optional glob pattern such as *.py or src/**/*.ts"
      }
    },
    "required": ["query"]
  }
}

Trong hệ sinh thái của Vie Agentic Skill, quy tắc khai báo này chính là nền tảng để các kỹ năng SKILL.md vận hành trơn tru trên Claude Code, OpenAI Codex, Antigravity và Windsurf.

The tool_use module demonstrates how to transform Claude from a text generator into an autonomous agent. The standard interaction cycle operates across 4 closed phases:

  1. Tool Declaration: The client supplies available tools defined with clean names, semantic descriptions, and formal JSON Schema parameter definitions.
  2. Model Decision: Claude identifies tool requirements and yields a message block with stop_reason: "tool_use" containing the unique invocation ID and parsed arguments.
  3. Local Execution: The host runtime executes the local function (such as querying an operational database or inspecting the filesystem) within bounded security policies.
  4. Result Injection: The client responds with a tool_result block referencing the original tool use ID, allowing Claude to synthesize the final verified answer.
