Để AI Agent xem video: Trích xuất khung hình, phụ đề và phân tích đa phương thứcLet AI Agents Inspect Videos: Frame Extraction, Captions, and Multimodal Analysis

Biên soạn bởi Vie Agentic Skill · Dựa trên runbook trong catalogPrepared by Vie Agentic Skill · Based on catalog runbooks

Khi bạn đưa cho AI coding agent một liên kết YouTube hoặc video ghi màn hình, phần lớn công cụ hiện nay chỉ bóc tách phụ đề chữ để trả lời. Nhưng với video kỹ thuật, slide bài giảng hay thao tác giao diện, phụ đề chữ không thể diễn tả được những gì thực sự hiển thị trên màn hình.

When you hand an AI coding agent a YouTube URL or a local screen recording, most tooling only extracts text captions. Yet for software tutorials, lecture slides, and UI walkthroughs, transcript alone cannot establish what actually appeared on screen.

1. Giới hạn khi chỉ đọc phụ đề video1. The limits of transcript-only video reasoning

Một ảo tưởng phổ biến trong các quy trình AI là cho rằng một bản transcript đầy đủ là đủ để "hiểu" video. Thực tế chứng minh ngược lại trong các tình huống kỹ thuật phổ biến:

  • Người nói không đọc toàn bộ slide: Diễn giả chỉ nói "như các bạn thấy trên sơ đồ này" hoặc "hãy chú ý vào thông số ở góc phải" mà không đọc tên thành phần hay giá trị đo lường.
  • Sửa lỗi và code trực tiếp: Khi một lập trình viên gõ code trên màn hình, họ thường im lặng hoặc chỉ giải thích ý niệm chung. Phụ đề không thể cung cấp cú pháp, tên hàm hay đường dẫn file thật.
  • Minh họa giao diện ứng dụng: Trong các buổi demo sản phẩm hoặc video kiểm thử, sự sai lệch màu sắc, layout vỡ hay thông báo lỗi popup chỉ tồn tại ở dạng pixel hình ảnh.

Kỹ năng watch do Bradley Bonanno phát triển giải quyết triệt để vấn đề này bằng cách kết hợp song song cả phụ đề chữ lẫn khung hình thị giác có mốc thời gian đồng bộ, hoặc ủy quyền cho mô hình đa phương thức chuyên dụng.

A common fallacy in AI workflows is assuming an audio transcript is sufficient to understand a video. In practice, technical workflows quickly break down:

  • Speakers rarely read slides aloud: A presenter says "as illustrated in this diagram" or "notice the metric on the top right" without speaking the actual component names or values.
  • Live coding and debugging: When an engineer codes on screen, they often type in silence. Captions omit the exact syntax, identifiers, and configuration paths shown.
  • Visual UI inspection: In product walkthroughs or QA bug reports, broken layouts, styling regressions, or ephemeral toast warnings exist purely as pixels.

The watch skill created by Bradley Bonanno bridges this gap by marrying timestamped frames with caption streams, or offloading the entire video to a dedicated multimodal foundation model.

2. Hai engine linh hoạt: Gemini Model và Local Pipeline2. Two engines: Gemini Multimodal and Local Pipeline

Skill watch được thiết kế với hai kiến trúc phân tách rõ ràng, phù hợp cho cả môi trường làm việc đám mây lẫn máy trạm cục bộ:

Tiêu chí Gemini Engine (--engine gemini) Local Engine (--engine local)
Cơ chế xử lý Mô hình Gemini của Google "xem" trực tiếp cả audio và video Trích xuất khung hình bằng FFmpeg + Phụ đề WebVTT / Whisper
Yêu cầu mạng & API Key Cần GEMINI_API_KEY (miễn phí từ AI Studio) Không cần API key (hoạt động 100% offline nếu có model)
Tài nguyên máy trạm Gần như bằng 0; URL YouTube gửi thẳng đến Google Cần cài yt-dlp, ffmpeg, tùy chọn RAM cho WhisperX
Xử lý tệp cục bộ Tải lên Google Files API và tự xóa ngay sau khi trả lời Xử lý hoàn toàn trong thư mục tạm trên ổ cứng của bạn

Khi sử dụng engine Gemini, với video YouTube, URL được gửi trực tiếp mà không cần tải file về máy. Đối với video cục bộ, script upload qua Files API của Google, chờ mô hình xem xong, nhận câu trả lời có mốc thời gian và lập tức xóa tệp trên đám mây.

The watch skill is architected around two explicit engines tailored for cloud or local workstations:

Dimension Gemini Engine (--engine gemini) Local Engine (--engine local)
Mechanism Google Gemini model directly ingests full audio and video tracks FFmpeg frame extraction + WebVTT / Whisper speech transcription
Network & Keys Requires GEMINI_API_KEY (free from Google AI Studio) Zero API keys required (fully offline with local binaries)
Host Footprint Near-zero local CPU/GPU; YouTube URLs are relayed directly Requires local yt-dlp, ffmpeg, and disk/RAM for WhisperX
Local Media Files Uploaded to Google Files API, then purged after answer generation Processed strictly within a local disposable temporary directory

With the Gemini engine, YouTube links skip downloading entirely. For local videos, the script uploads media through Google's Files API, fetches the timestamped response, and promptly deletes the uploaded artifact.

3. Bốn cấp độ trích xuất khung hình và kiểm soát token3. Four detail levels and image token budgeting

Khi chạy engine cục bộ, đưa hàng nghìn ảnh chụp màn hình vào context của LLM sẽ gây tốn kém chi phí token và làm chậm tốc độ phản hồi. watch chia nhỏ thành 4 cấp độ chi tiết với thuật toán phát hiện chuyển cảnh thông minh:

  • transcript: Không xuất ảnh. Chỉ tải phụ đề native khi có sẵn, không tải media tốn dung lượng mạng.
  • efficient: Trích xuất keyframe tốc độ cao, giới hạn cứng tối đa 50 khung hình.
  • balanced (Khuyên dùng): Thuật toán nhận diện cảnh chuyển động (scene detection), tự động co giãn FPS (auto_fps) và chặn trên tối đa 100 khung hình.
  • token-burner: Trích xuất cảnh chuyển động không giới hạn khung hình, chỉ dùng khi cần soi chi tiết từng bước phức tạp.
# Chạy xem video với mức chi tiết cân bằng mặc định
python3 scripts/watch.py "https://www.youtube.com/watch?v=EXAMPLE" --detail balanced

# Chỉ lấy phụ đề chữ để duyệt nhanh nội dung
python3 scripts/watch.py "https://www.youtube.com/watch?v=EXAMPLE" --detail transcript

When running locally, dumping hundreds of raw frames into an LLM context exhausts image token budgets and increases latency. watch structures extraction into four tiered detail modes backed by scene-change heuristics:

  • transcript: Zero image frames. Extracts native captions without pulling heavy video binaries.
  • efficient: Fast I-frame keyframe extraction, strictly capped at 50 frames.
  • balanced (Default / Recommended): Scene-aware frame sampling with adaptive auto_fps, capped at 100 frames.
  • token-burner: Uncapped scene detection for granular, frame-by-frame visual inspection.
# Run balanced visual inspection
python3 scripts/watch.py "https://www.youtube.com/watch?v=EXAMPLE" --detail balanced

# Rapid transcript-only intake
python3 scripts/watch.py "https://www.youtube.com/watch?v=EXAMPLE" --detail transcript

4. Phân tích mốc thời gian cụ thể và xử lý lỗi4. Focused timestamp intervals and failure recovery

Trong thực tế, bạn thường chỉ quan tâm đến một đoạn ngắn trong bài giảng dài 2 tiếng. watch hỗ trợ tinh chỉnh phạm vi cực kỳ chính xác:

  • Khoảng thời gian (Focus range): Dùng --start 14:20 --end 18:30 để chỉ bóc tách phụ đề và khung hình trong 4 phút quan trọng.
  • Các mốc thời gian cụ thể (Discrete cues): Dùng --timestamps 4:32,7:10,9:55 để lấy đúng các frame tại các điểm thời gian người nói chuyển chủ đề.
  • Xử lý lỗi 403 / YouTube CDN: Khi gặp lỗi chặn từ nguồn tải, nâng cấp `yt-dlp` bằng lệnh của package manager (ví dụ brew upgrade yt-dlp hoặc pipx upgrade yt-dlp) và chạy lại. Script tuyệt đối không can thiệp tắt kiểm tra chứng chỉ TLS hay can thiệp cookie trái phép.
# Soi kỹ đoạn demo từ phút 12:00 đến 14:30
python3 scripts/watch.py video.mp4 --start 12:00 --end 14:30 --timestamps 12:45,13:10

Technical users rarely inspect an entire two-hour recording when diagnosing an issue. watch provides focused slicing:

  • Focus windows: Use --start 14:20 --end 18:30 to isolate frames and captions within the exact four-minute window.
  • Discrete cue timestamps: Use --timestamps 4:32,7:10,9:55 to pinpoint exact slides or UI transitions.
  • 403 CDN errors: When download CDNs return access errors, upgrade yt-dlp via your system package manager (e.g. brew upgrade yt-dlp or pipx upgrade yt-dlp). The tool maintains security hygiene without disabling TLS verification or cycling cookies insecurely.
# Inspect an exact local demonstration segment
python3 scripts/watch.py video.mp4 --start 12:00 --end 14:30 --timestamps 12:45,13:10

5. Cài đặt và sử dụng trong dự án với VAS5. Installing and running with VAS

Kỹ năng watch đã được đóng gói độc lập theo chuẩn Open Agent Skills, giữ nguyên giấy phép MIT và được quản lý hoàn toàn bằng Python CLI:

# Cài đặt chế độ link cho Antigravity (Universal)
./vas install watch --target antigravity --mode link

# Cài đặt chế độ copy độc lập cho Claude Code hoặc Cursor
./vas install watch --target claude --mode copy --dest "/path/to/project/.claude/skills"

# Kiểm tra trạng thái cài đặt
./vas status --target claude --dest "/path/to/project/.claude/skills"

Sau khi cài đặt, bạn chỉ cần ra lệnh cho agent: "Hãy xem video tại liên kết này và tóm tắt các điểm kiến trúc chính cùng hình ảnh minh họa tương ứng". Agent sẽ tự động gọi scripts/watch.py, đọc các khung hình và trả lời chính xác dựa trên bằng chứng thực tế.

The watch skill is packaged as an independent module under the Open Agent Skills specification, preserving its MIT license and managed via the dependency-free VAS CLI:

# Install in link mode for Antigravity (Universal)
./vas install watch --target antigravity --mode link

# Install in standalone copy mode for Claude Code or Cursor
./vas install watch --target claude --mode copy --dest "/path/to/project/.claude/skills"

# Verify installation status
./vas status --target claude --dest "/path/to/project/.claude/skills"

Once installed, instruct your coding agent: "Inspect the video at this URL and summarize the architectural changes with matching visual evidence". The agent invokes scripts/watch.py, inspects the extracted frames, and delivers grounded answers.
