Thiết lập máy không màn hình qua SSH mà không lộ mật khẩu quản trịSet up unattended machines over SSH without exposing admin passwords

Biên soạn bởi Vie Agentic Skill · Dựa trên runbook và mã nguồn từ Kun ChenPrepared by Vie Agentic Skill · Based on runbooks and scripts by Kun Chen

Biến một chiếc Mac mini đặt góc bàn, một máy chủ Linux hay một PC Windows thành trạm làm việc từ xa chạy 24/7 mà không cần cắm màn hình hay bàn phím là nhu cầu phổ biến của kỹ sư phần mềm. Tuy nhiên, nếu nhờ AI agent tự động cấu hình qua SSH theo cách thông thường, bạn rất dễ phải dán mật khẩu quản trị vào khung chat hoặc truyền qua tham số dòng lệnh — khiến mật khẩu bị lưu vĩnh viễn trong lịch sử hội thoại và nhật ký tiến trình. Kỹ năng headless giải quyết triệt để bài toán này bằng cơ chế cách ly bí mật qua file descriptor và quy trình cấu hình bất biến.

Bài viết này phân tích kiến trúc bảo mật của công cụ secret-run.sh, quy trình 7 bước cấu hình từ xa cho macOS, Linux và Windows, những đánh đổi an toàn khi bật tự động đăng nhập sau khởi động lại, cũng như phạm vi kiểm chứng thực tế trong thư viện VAS.

Turning a spare Mac mini, a Linux box, or a Windows PC into a 24/7 unattended remote workstation without a monitor or keyboard is a common engineering task. However, delegating SSH provisioning to an AI coding agent normally tempts users to paste admin passwords into chat prompts or pass them on the command line—leaking credentials into model logs, shell history, and process tables. The headless skill eliminates this risk through file-descriptor secret piping and idempotent provisioning scripts.

This guide examines the architecture of secret-run.sh, the seven-step remote setup workflow across macOS, Linux, and Windows, the security trade-offs of unattended reboot configuration, and the verification boundaries recorded in the VAS catalog.

1. Cách ly mật khẩu khỏi AI agent bằng File Descriptor 31. Isolating secrets from AI agents via File Descriptor 3

Quy tắc cốt lõi của bộ kỹ năng headless là AI agent chỉ được biết tên tham chiếu của bí mật, tuyệt đối không bao giờ nhìn thấy giá trị mật khẩu thật. Thay vì yêu cầu người dùng nhập mật khẩu vào cửa sổ chat, người dùng lưu mật khẩu vào trình quản lý bí mật cục bộ (Automic Vault, 1Password CLI, Bitwarden CLI hoặc macOS Keychain) và chỉ cung cấp chuỗi định danh (ví dụ av:mac-mini-admin hoặc op://Private/mac-mini/password).

Khi cần chạy lệnh quản trị từ xa hoặc mở kết nối SSH lần đầu, agent gọi wrapper scripts/secret-run.sh. Kịch bản này đọc giá trị mật khẩu từ kho lưu trữ và mở file descriptor 3 (FD 3) chỉ tồn tại trong bộ nhớ của tiến trình con:

# Agent chỉ truyền tham chiếu bí mật (ví dụ av:mac-mini-admin), không có mật khẩu trên dòng lệnh
scripts/secret-run.sh av:mac-mini-admin \
  scripts/mac/connect.sh --host 192.168.1.50 --user admin

# Bên trong secret-run.sh: truyền qua FD 3 tới sudo -S hoặc SSH_ASKPASS tạm thời
exec 3< <(produce_secret "$SPEC")
"$@"
exec 3<&-

Nhờ cơ chế này, giá trị mật khẩu không xuất hiện trong ps aux, không lưu vào ~/.zsh_history, không bị ghi vào tệp cấu hình trên đĩa và không bao giờ đi vào context window của mô hình ngôn ngữ lớn.

The foundational security rule of the headless skill is strict credential isolation: the AI agent only ever handles a secret reference name, never the plaintext password. Before starting, the human operator stores the target machine's admin password in a local secret store (Automic Vault, 1Password CLI, Bitwarden CLI, or macOS Keychain) and gives the agent only the reference URI (such as av:mac-mini-admin or op://Private/mac-mini/password).

Whenever a remote sudo prompt or initial SSH password exchange is required, the agent invokes scripts/secret-run.sh. This wrapper resolves the secret locally and pipes it exclusively through file descriptor 3 (FD 3) to child utilities:

# The agent passes only the secret reference URI; no password appears in argv
scripts/secret-run.sh av:mac-mini-admin \
  scripts/mac/connect.sh --host 192.168.1.50 --user admin

# Inside secret-run.sh: secret bytes flow over FD 3 to sudo -S or an ephemeral SSH_ASKPASS
exec 3< <(produce_secret "$SPEC")
"$@"
exec 3<&-

Because the secret is consumed directly from FD 3 in memory, it never appears in process arguments (ps aux), shell history files, repository configuration files, or the LLM's conversation transcript.

2. Lựa chọn nền tảng: macOS, Linux/NixOS và Windows2. Platform architecture: macOS, Linux/NixOS and Windows

Bộ kỹ năng headless hỗ trợ ba hệ điều hành mục tiêu với chiến lược quản lý cấu hình phù hợp từng nền tảng:

  • macOS (Apple silicon hoặc Intel): Sử dụng Determinate Nix kết hợp với nix-darwin và mô-đun khai báo modules/darwin/headless.nix. Toàn bộ thiết lập nguồn điện (pmset chống ngủ máy), khóa màn hình, tường lửa, SSH daemon, chia sẻ màn hình (Screen Sharing) và Homebrew được khai báo tập trung trong một flake duy nhất.
  • Linux (NixOS hoặc bản phân phối truyền thống): Hỗ trợ hai nhánh rõ ràng. Với NixOS, skill dùng mô-đun modules/nixos/headless.nix (và hỗ trợ cài mới từ xa bằng nixos-anywhere). Với Ubuntu, Debian, Fedora, Arch hoặc RHEL, skill cung cấp bộ kịch bản POSIX scripts/linux/ không phụ thuộc bản phân phối, tác động trực tiếp vào systemd-logind, targets ngủ của systemd và /etc/ssh/sshd_config.d/headless.conf.
  • Windows 11 và Windows Server 2025: Sử dụng tập lệnh PowerShell từ xa thông qua OpenSSH Server để tắt chế độ ngủ (powercfg), cấu hình sshd_config, bật Remote Desktop (RDP) kèm Network Level Authentication (NLA), và tùy chọn cài đặt gói phần mềm qua winget.

The headless skill provides tailored provisioning pipelines for three major operating system families:

  • macOS (Apple silicon or Intel): Powered by Determinate Nix, nix-darwin, and the declarative modules/darwin/headless.nix module. Power management (pmset sleep disabling), screen lock policies, application firewall rules, SSH hardening, Screen Sharing, and Homebrew packages are managed cleanly through a single Nix flake.
  • Linux (NixOS or distro-neutral Linux): Supports two distinct tracks. The NixOS track uses modules/nixos/headless.nix (with optional bare-metal installation via nixos-anywhere). The distro-neutral track (Ubuntu, Debian, Fedora, Arch, RHEL) uses idempotent POSIX shell scripts under scripts/linux/ to configure systemd-logind, mask systemd sleep targets, and write drop-in rules to /etc/ssh/sshd_config.d/headless.conf.
  • Windows 11 and Windows Server 2025: Uses remote PowerShell scripts over OpenSSH Server to disable standby timeouts via powercfg, harden sshd_config, enable Remote Desktop (RDP) with Network Level Authentication (NLA), and install baseline packages through winget.

3. Quy trình 7 bước thiết lập bất biến và quy tắc khóa SSH3. The 7-step idempotent workflow and SSH key lockout guards

Một lỗi tai hại khi cấu hình máy từ xa là tắt xác thực mật khẩu SSH (PasswordAuthentication no) trước khi xác nhận khóa công khai (SSH public key) đã hoạt động, dẫn đến mất quyền truy cập hoàn toàn vào máy không có màn hình. Để ngăn chặn rủi ro này, headless chia quy trình thành 7 bước tuần tự và bất biến (idempotent — có thể chạy lại nhiều lần an toàn):

  1. Bước 1 — Khám phá & sinh cấu hình (new-config.sh): Thu thập thông tin máy đích và tạo thư mục cấu hình cục bộ từ mẫu chuẩn mà không ghi đè các chỉnh sửa của người dùng.
  2. Bước 2 — Ghim host key & kiểm tra khóa SSH (connect.sh): Quét khóa định danh máy chủ (ưu tiên ssh-ed25519), cài đặt khóa công khai của người dùng lên máy đích và kiểm tra đăng nhập không mật khẩu trước khi cho phép chuyển sang chế độ chỉ dùng khóa (key-before-key-only rule).
  3. Bước 3 — Thiết lập quyền quản trị & tự động đăng nhập (admin.sh): Cấu hình nhóm quản trị, chính sách sudo và các tác vụ một lần.
  4. Bước 4 — Áp dụng cấu hình hệ thống (apply.sh): Đồng bộ cấu hình và kích hoạt thay đổi về nguồn điện, mạng, dịch vụ từ xa và gói phần mềm.
  5. Bước 5 — Cài đặt lớp truy cập khẩn cấp (Escape Hatch): Luôn duy trì ít nhất hai đường truy cập độc lập (ví dụ SSH qua mạng LAN cùng với Tailscale SSH hoặc Screen Sharing / RDP) để phòng trường hợp một dịch vụ gặp sự cố.
  6. Bước 6 — Kiểm tra trạng thái thực tế (verify.sh): Đối chiếu từng thông số hệ thống với cấu hình mong muốn và báo cáo kết quả Đạt/Lỗi rõ ràng.
  7. Bước 7 — Khởi động lại có kiểm soát (restart.sh): Khởi động lại máy từ xa, chờ kết nối SSH phục hồi và tự động chạy lại verify.sh để chứng minh máy sống sót sau khi mất nguồn.

A classic failure mode in remote server administration is disabling SSH password authentication (PasswordAuthentication no) before verifying that public-key login actually succeeds—permanently locking the operator out of a monitorless machine. To prevent lockouts, headless enforces a seven-step idempotent sequence:

  1. Step 1 — Discovery & Config Generation (new-config.sh): Gather target facts and scaffold a local configuration directory without clobbering existing user customizations.
  2. Step 2 — Host-Key Pinning & Key Enrollment (connect.sh): Pin the server's ssh-ed25519 host key, install the operator's public key, and verify passwordless key login before any sshd lockdown occurs (the key-before-key-only rule).
  3. Step 3 — Admin Privileges & One-Shot Setup (admin.sh): Configure admin group membership, sudo policy, and OS-specific bootstrap settings.
  4. Step 4 — Declarative Apply (apply.sh): Sync configuration files and converge power settings, sleep prevention, remote desktop services, and packages.
  5. Step 5 — Escape Hatch Provisioning: Maintain at least two independent remote access paths (for example, LAN OpenSSH plus Tailscale SSH or Screen Sharing / RDP) so a single service failure never bricks remote access.
  6. Step 6 — Live State Verification (verify.sh): Audit actual system settings against expected state with explicit pass/fail checks.
  7. Step 7 — Verified Reboot (restart.sh): Trigger a clean reboot, poll until SSH returns, and automatically re-run verify.sh to prove the machine survives unattended power cycles.

4. Đánh đổi bảo mật khi tự động đăng nhập sau khởi động lại4. Security trade-offs of unattended reboot and auto-login

Khi cấu hình máy chạy không màn hình, câu hỏi quan trọng nhất mà agent phải hỏi người dùng là: Máy có cần tự khởi động lại hoàn toàn sau khi mất điện hoặc cập nhật hệ điều hành mà không cần gắn bàn phím hay không?

  • Trên macOS: Nếu bật mã hóa ổ đĩa FileVault, sau khi khởi động lại máy sẽ dừng ở màn hình mở khóa Pre-boot (trước khi hệ điều hành và mạng Wi-Fi/SSH kịp chạy). Do đó, nếu chọn chế độ tự phục hồi hoàn toàn sau mất điện (autoLogin = true), người dùng buộc phải tắt FileVault và cho phép tạo tệp /etc/kcpassword (mã hóa XOR). Để bù đắp rủi ro vật lý khi máy đặt ở nơi không an toàn, headless tự động kích hoạt một LaunchAgent khóa màn hình ngay lập tức sau khi phiên đăng nhập khởi tạo xong.
  • Trên Windows: Để các tác vụ cấp người dùng chạy ngay sau khi bật máy kết hợp với khóa màn hình tức thời, hệ thống lưu thông tin đăng nhập tự động vào kho LSA secret của Windows kèm theo Scheduled Task gọi rundll32.exe user32.dll,LockWorkStation ngay khi đăng nhập. Nếu chỉ cần truy cập SSH hoặc RDP thông thường, người dùng nên tắt autoLogin vì dịch vụ sshd và TermService vốn đã chạy ở cấp hệ thống trước khi đăng nhập.

When provisioning an unattended machine, the most critical architectural decision the agent must clarify with the user is: Must the machine return online automatically after a power outage or OS update without anyone attaching a physical keyboard?

  • On macOS: When FileVault full-disk encryption is active, a cold boot halts at the pre-boot unlock screen before macOS loads networking or sshd. Enabling true unattended recovery (autoLogin = true) therefore requires disabling FileVault and writing an obfuscated /etc/kcpassword file. To mitigate physical console exposure once booted, headless pairs auto-login with a LaunchAgent that immediately locks the GUI session upon login.
  • On Windows: Both OpenSSH Server (sshd) and Remote Desktop (TermService) run as system services before any user logs in. Auto-login (which stores credentials in a Windows LSA secret and triggers an immediate LockWorkStation scheduled task) is only necessary when user-session tray apps must start on boot. For pure SSH or RDP servers, keeping autoLogin disabled is the safer default.

5. Phạm vi kiểm chứng và cách cài đặt trong VAS5. Verification scope and installation in VAS

Trong thư viện VAS, gói kỹ năng headless được nhập nguyên bản từ commit fe1a381c6f382ec3c9822da0e706484414bc63e0 của tác giả Kun Chen (giấy phép MIT), bao gồm đầy đủ 55 tệp: runbook chính, 5 tài liệu tham chiếu nền tảng (macOS, Linux, Windows, Tailscale, quản lý bí mật), các mô-đun Nix khai báo và 29 kịch bản shell giữ nguyên quyền thực thi (0755). Trong quá trình nhập kho, VAS đã kiểm chứng tĩnh toàn bộ cây tệp, mã băm SHA-256, cú pháp đóng gói và manifest cài đặt mà không tự ý thực thi các lệnh cấp quyền hay kết nối SSH ra ngoài. Khi áp dụng vào máy thật, bạn nên đọc kỹ các tệp trong references/ và kiểm tra từng bước với verify.sh.

Bạn có thể cài đặt kỹ năng này vào không gian làm việc của mình bằng VAS CLI:

# Cài đặt skill cho Antigravity hoặc bất kỳ AI agent nào được hỗ trợ
./vas install headless --target antigravity --mode link

# Xem chi tiết cấu trúc tệp và hướng dẫn sử dụng
./vas show headless

In the VAS catalog, the headless skill is packaged from upstream commit fe1a381c6f382ec3c9822da0e706484414bc63e0 by Kun Chen under the MIT License. It includes all 55 files: the primary runbook, five platform reference guides (macOS, Linux, Windows, Tailscale, and secrets), declarative Nix modules, and 29 shell scripts with preserved executable permissions (0755). During catalog ingestion, VAS statically verified the complete file tree, SHA-256 digests, executable bits, and standalone installation manifest without running live SSH provisioning against external hosts. Always review the platform guides under references/ and validate changes with verify.sh on your target hardware.

Install the skill into your workspace using the local VAS CLI:

# Install the skill for Antigravity or your preferred coding agent
./vas install headless --target antigravity --mode link

# Inspect the runbook and bundled scripts
./vas show headless
