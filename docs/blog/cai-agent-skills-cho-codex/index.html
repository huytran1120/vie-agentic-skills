Cài Agent Skills cho Codex: đúng thư mục, kiểm tra hoạt độngInstall Agent Skills in Codex: paths, discovery and verification

Biên soạn bởi Vie Agentic Skill · Cập nhật By Vie Agentic Skill · Updated 2026-11-06

Để Codex nhận một skill, cần đặt cả thư mục skill vào nơi Codex đọc, rồi kiểm tra việc nhận diện trong phiên làm việc. Bài này dùng CLI VAS để cài vào .agents/skills và giữ thông tin quản lý bản cài.

Codex needs the complete skill folder in a location it scans. This guide uses the VAS CLI to install into .agents/skills, retain installation records and verify discovery in a working session.

1. Chọn phạm vi trước khi cài1. Choose the scope first

Theo tài liệu Codex, skill trong repository nằm ở .agents/skills; skill cá nhân dùng chung nằm ở ~/.agents/skills. Codex tìm các thư mục trong chuỗi từ thư mục làm việc tới gốc repository. Hãy mở đúng dự án trước khi kiểm tra.

Ở phiên bản VAS được dùng cho bài này, --target codex vẫn ánh xạ tới .codex/skills. Các lệnh bên dưới chủ đích dùng --target workspace và đích .agents/skills theo tài liệu Codex hiện tại. Đây là lựa chọn thư mục cài, không phải đổi ứng dụng đang dùng. Khi dùng Copy Agent Prompt trên website, cũng cần đọc lại đường dẫn đích; đừng mặc định hai thư mục tương đương trên mọi phiên bản.

Chuẩn bị Python 3.9+ cho CLI VAS, Git nếu cần clone và một bản Codex có hỗ trợ skills. Cài skill chỉ đưa hướng dẫn và tệp phụ trợ vào máy; công cụ mà runbook sử dụng, chẳng hạn trình duyệt hoặc Playwright, vẫn là yêu cầu riêng.

The Codex documentation places repository skills in .agents/skills and personal skills in ~/.agents/skills. Codex scans locations between the working directory and repository root, so open the intended project when checking discovery.

In the VAS version used here, --target codex still maps to .codex/skills. These examples deliberately use --target workspace with an explicit .agents/skills destination to match current Codex documentation. This selects an installation folder, not a different application. If you use Copy Agent Prompt on the website, inspect its destination too; the two paths are not interchangeable across every version.

Prepare Python 3.9+ for the VAS CLI, Git if cloning is necessary, and a Codex version with skill support. Installing a skill provides instructions and supporting files. Runtime tools used by the runbook, including browsers or Playwright, remain separate prerequisites.

2. Cài một skill vào dự án đích2. Install into the target project

Nếu đã có VAS, dùng bản clone hiện tại. Nếu chưa, clone một lần rồi chạy CLI từ gốc kho. Ví dụ dùng webapp-testing; đọc runbook, giấy phép và các scripts trước khi cho phép thực thi.

Use an existing VAS clone when available. Otherwise, clone once and run the CLI from its root. The example uses webapp-testing; inspect its runbook, license and scripts before permitting execution.

git clone https://github.com/huytran1120/vie-agentic-skills.git
cd vie-agentic-skills
./vas show webapp-testing
./vas install webapp-testing --target workspace --mode copy --dest "/absolute/path/to/project/.agents/skills"
./vas status --target workspace --dest "/absolute/path/to/project/.agents/skills"

Thay đường dẫn tuyệt đối bằng dự án thật. --dest phải là thư mục chứa các skill, không phải thư mục con của riêng skill. Kết quả cần có cấu trúc như dưới đây; nội dung phụ trợ tùy inventory của skill.

Replace the absolute path with your project. --dest names the directory containing skills, not the individual skill folder. Expect this layout; supporting contents depend on the inventory.

project/
  .agents/
    skills/
      .vas-manifest.json
      webapp-testing/
        SKILL.md
        scripts/
        examples/

copy tạo bản độc lập. Nếu chọn link, phải giữ nguyên thư mục nguồn; di chuyển hoặc xóa clone VAS có thể làm hỏng liên kết. Trên Windows, có thể dùng python3 vas.py thay cho ./vas trong một shell đã cấu hình Python.

copy creates a standalone installation. With link, the source must remain available; moving or deleting the VAS clone can break discovery. On Windows, use python3 vas.py instead of ./vas in a shell configured for Python.

3. Kiểm tra nhận diện và một tác vụ nhỏ3. Verify discovery and a small task

  1. Mở SKILL.md tại đích, kiểm tra frontmatter có name, description và các tệp được tham chiếu tồn tại.
  2. Mở hoặc khởi động lại phiên Codex trong đúng dự án nếu skill mới chưa xuất hiện. Với CLI/IDE hỗ trợ, dùng /skills hoặc gõ $ để tìm skill.
  3. Gọi skill rõ ràng trong một tác vụ nhỏ và yêu cầu agent báo những công cụ còn thiếu trước khi chạy.
  1. Open the installed SKILL.md. Check its name, description and referenced files.
  2. Open or restart a Codex session in the intended project if the new skill is absent. In supported CLI/IDE interfaces, use /skills or type $ to find it.
  3. Request the skill explicitly for a small task and ask the agent to report missing tools before execution.
Áp dụng $webapp-testing để lập kế hoạch kiểm tra trang đăng nhập local.
Trước tiên xác nhận URL, tài khoản thử và công cụ đã có.
Chưa cài thêm dependency, gửi dữ liệu hoặc đổi mã nguồn.
Nêu các bước kiểm tra và phần chưa thể thực hiện.
Use $webapp-testing to plan checks for the local login page.
First confirm the URL, test account and available tools.
Do not install dependencies, send data or change source code yet.
Report the planned checks and anything currently blocked.

Có tệp trên đĩa, có skill trong danh sách và thực thi thành công là ba mốc khác nhau. Báo cáo nên phân biệt chúng. Một runbook được nhận diện vẫn có thể chưa chạy được vì thiếu trình duyệt, dữ liệu thử hoặc quyền truy cập.

Files on disk, a discoverable skill and a successful task are three different milestones. Report them separately. A discovered runbook can still be blocked by missing browsers, test data or permissions.

4. Phạm vi cá nhân, cập nhật và gỡ4. Personal scope, updates and removal

Để dùng chung trên máy, chọn --dest "$HOME/.agents/skills" trong Bash/Zsh và dùng cùng đích cho status, uninstall. Tránh cài trùng tên ở cả phạm vi cá nhân và dự án khi chưa hiểu phiên bản Codex sẽ hiển thị những bản nào.

Khi cập nhật, xem thay đổi nguồn và sao lưu chỉnh sửa cục bộ trước. Nếu CLI báo xung đột, kiểm tra quyền sở hữu và khác biệt thay vì xóa receipt hoặc ghi đè thủ công. Gỡ bản do CLI quản lý bằng đúng target và đích đã cài:

For personal use across projects, choose --dest "$HOME/.agents/skills" in Bash/Zsh and keep that destination for status and uninstall. Avoid duplicate skill names across personal and repository locations until you understand how your Codex version presents them.

Before updating, review upstream changes and preserve local edits. Investigate ownership and differences when the CLI reports conflicts instead of deleting receipts or overwriting files manually. Remove a CLI-managed installation using its original target and destination:

./vas uninstall webapp-testing --target workspace --dest "/absolute/path/to/project/.agents/skills"

Nếu chưa nhận skill, dùng quy trình kiểm tra discovery. Để hiểu vai trò của từng lớp cấu hình, đọc Skills, MCP và AGENTS.md.

If discovery fails, follow the skill troubleshooting guide. For configuration boundaries, read Skills, MCP and AGENTS.md.
